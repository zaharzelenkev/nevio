# NEVIO · Мультистрановая архитектура (СНГ)

Документ описывает, как проект масштабируется с Беларуси на весь СНГ без изменения
текущей белорусской версии. **Беларусь (BY) — это полноценная страна-конфигурация,
её поведение не менялось**: та же логика, те же пункты меню, те же промпты, тот же
раздел «Ресурсы» (ЕИОР + Аду.бай).

## 1. Принципы

1. **Ничего не удаляем.** Все белорусские сущности (ЦТ/ЦЭ, экзамены после 9 класса,
   база знаний `CT_KNOWLEDGE_BASE`, живое зеркало ЕИОР/Аду.бай) остались на месте
   и обёрнуты в конфиг `country: BY`.
2. **Один файл — одна логика.** Telegram Mini App и сайт используют один `index.html`
   и один сетевой слой: инфраструктура и квоты ИИ не удваиваются.
3. **100% бесплатно для владельца.** Только бесплатные модели
   (OpenRouter `:free` / роутер `openrouter/free`, Groq free tier), бесплатные
   прокси-цепочки для «живых» страниц, локальное хранение, передача заданий
   и результатов кодами (без сервера), опциональная синхронизация через
   бесплатный тариф Firebase Spark. Платных сервисов нет.
4. **Статичная база знаний вместо генерации.** Структура экзаменов, критерии
   оценивания, базы правил и формулы по каждой стране лежат в коде как статичные
   тексты — это быстрее и не тратит бесплатные квоты запросов к моделям.

## 2. Определение страны пользователя

Порядок при первом запуске мини-аппа:

1. **Язык Telegram** (`initDataUnsafe.user.language_code`):
   `ru`/`be` → Беларусь, `kk` → Казахстан, `uz` → Узбекистан.
2. **Геолокация** (только подсказка): бесплатный `ipapi.co/json/` с таймаутом 3.5 с —
   подсвечивает карточку страны на экране выбора. Ничего не выбирает автоматически.
3. **Ручной выбор** — страница выбора страны, всегда доступна в «Настройки →
   Страна и язык».

Правила совместимости:

- У существующих пользователей (в `localStorage` уже есть данные) без указания
  страны — страна автоматически становится `BY`, страница выбора не показывается.
  Поведение текущих белорусских пользователей не изменилось.
- Смена страны в настройках не трогает роль, историю запросов и прогресс.

## 3. Конфиг страны (контракт)

Все страны описаны в `NEVIO_COUNTRIES` (в `index.html`). Контракт конфига:

| Поле | Назначение |
|---|---|
| `id`, `flag`, `nameLocal()` | идентификатор, флаг, название (может зависеть от языка интерфейса) |
| `langs`, `defaultLang` | доступные языки интерфейса и язык по умолчанию |
| `exam.primary` | главный экзамен: `title`, `short`, `structure`, `criteria` (статичные тексты) |
| `exam.secondary` | экзамен после 9 класса: `title`, `desc`, `info` |
| `ctSubjects`, `exam9Subjects`, `studySubjects` | списки предметов для форм |
| `ctModes`, `exam9Modes` | опции режимов подготовки |
| `kbForSubject(subject)` | статичная база знаний (формулы/даты) по предмету |
| `rules` | статичная база правил по группам: `math`, `physics`, `chemistry`, `lang`, `history`, `gramot` |
| `systemPrompt(role)`, `systemContext(base)` | системный промпт и его обогащение базой знаний |
| `ctPrepPrompt()`, `exam9Prompt()` | промпты подготовки к экзаменам |
| `t` | заголовки пунктов меню на языках страны (`{ru, kk}` / `{ru, uz}`) |
| `official.sections` | официальные порталы страны (открываются через общий live-механизм) |
| `tips` | советы для статичной справки «Формат и критерии» |
| `searchPh` | плейсхолдер поиска в разделе «Ресурсы» |

Правило «не дублировать»: базы формул для RU/KZ/UZ генерируются из
`CT_KNOWLEDGE_BASE` функцией `kbVariant()` (меняется только заголовок),
а правила используют общий реестр `RULE_BODIES` + ссылки на свой кодификатор/программу.

### Как добавить новую страну (например, Кыргызстан)

1. Добавить конфиг `KG: { ... }` в `NEVIO_COUNTRIES` по контракту выше.
2. Добавить правила `RULES_KG` (можно переиспользовать `RULE_BODIES` + свои `ref`).
3. Если нужен локальный язык интерфейса — добавить словарь в `I18N` и пункты
   меню `MENU_T_KG`; язык указать в `langs`.
4. Добавить `ky: 'KG'` в `detectCountryByTelegram()`.
5. Страна автоматически появится на экране выбора, в настройках, в меню,
   тестах, прогресс-трекинге и режиме учителя — код общий.

## 4. Точность и доверие («почему это верно»)

- В промпты действий `solve`, `explain`, `check_solution`, `ct_prep`, `exam9`,
  `summary` добавляется статичная **база правил страны** (`trustBlockFor`).
- Модель обязана закончить ответ разделами:
  - **«📚 Опора на программу»** — 2–4 конкретных правила из базы с разделом
    программы/кодификатора, которые реально использованы;
  - **«🧮 Оценка по критериям»** — как решение оценивается по критериям экзамена
    страны (ЕГЭ vs ЦТ vs ЕНТ vs тесты Узбекистана): за что полный балл, где теряются.
- Эти блоки рендерятся в золотые рамки («trust-box»).
- Действие **«Проверка решения по критериям»** (`check_solution`): принимает условие
  + решение ученика, проверяет по шагам и выдаёт балльную оценку по критериям
  с разбором потерь.

## 5. Прогресс и персонализация

- Каждый ответ в тестах записывается: предмет, тема (классифицируется статичным
  теггером по ключевым словам — без ИИ), верно/неверно.
- Действия (`solve`, `explain`, подготовка к экзаменам) пишутся в историю прогресса.
- Дашборд «Прогресс» (5-я вкладка): точность, число вопросов/тестов/действий,
  полосы по предметам, список **слабых мест** (точность < 75%).
- Рекомендации: «5 заданий по теме» (генерирует тренировку), «Объяснить тему»,
  «Тест по предмету». Всё хранится в `localStorage` (`nevioProgress_v1`),
  привязано к стране.

## 6. Режим учителя (B2B-канал)

Отдельный блок меню «Класс и аналитика» — **поверх** существующих учительских
функций (план урока, генератор заданий, варианты A/B и т.д. не тронуты):

- **Мои классы** — создание класса (название, предмет, класс), код доступа.
- **Задание классу** — ИИ генерирует вопросы по теме (один запрос), учитель видит
  предпросмотр с ответами, сохраняет — задание получает код.
- **Аналитика класса** — агрегация по попыткам: кто справился (имя, балл, время),
  средний результат, % верных ответов по каждому вопросу, **типичные ошибки**
  (вопросы с наибольшей долей ошибок + правильный ответ + объяснение).
- **Сторона ученика** — «Задания от учителя»: ввод кода, решение, автопроверка,
  результат уходит учителю.
- **Хранение и передача без серверов.** Задание целиком (вопросы и ответы)
  сжимается в «код задания» (NEV1…): учитель копирует его и отправляет ученикам,
  ученик вставляет код — задание открывается даже без интернета. Ученик после
  решения копирует «код результата» (NEVR1…) и присылает учителю, учитель вносит
  его в аналитику в один клик. Никаких серверов и оплат не требуется; аналитика
  работает на устройстве учителя + «Пробное прохождение» для проверки.
- **Опциональная автоматическая синхронизация.** Чтобы результаты приходили
  автоматически (коды при этом остаются запасным каналом), впишите URL
  **Firebase Realtime Database (тариф Spark — бесплатный навсегда, без банковской
  карты)** в константу `TEACHER_FIREBASE_DB` в `index.html` и задайте правила БД:

  ```json
  {
    "rules": {
      "nevio": { ".read": true, ".write": true }
    }
  }
  ```

  После этого задания и попытки синхронизируются между устройствами (REST API,
  без SDK и без платных сервисов).

## 7. Инфраструктура и бесплатные квоты (задача 6)

- **Ротация провайдеров.** Каждый запрос чередует стартового провайдера
  (OpenRouter → Groq → OpenRouter → …). OpenRouter использует только `:free`
  модели/роутер `openrouter/free`. Groq подключается, если владелец вписал
  бесплатный ключ в `GROQ_API_KEY`; при сбое/429/404 происходит фолбэк на
  следующую модель и следующего провайдера. Без ключа Groq поведение ровно
  прежнее (только OpenRouter).
- **Статичная база знаний.** Структура экзаменов, критерии, правила, формулы,
  даты по всем странам — статичные тексты в коде: не генерируются и не тратят
  квоты. Справка «Формат и критерии» вообще не делает запросов к ИИ.
- **Один бэкенд на две витрины.** Telegram Mini App и сайт — это один
  `index.html` и один сетевой слой; лимиты не расходуются вдвое.
- **Кэш «живых» страниц.** Раздел «Ресурсы» уже кэширует официальные страницы
  (6 ч в памяти/`localStorage`) — для новых стран используется тот же механизм.
- **Что проверить при росте нагрузки:** если упираемся в лимиты OpenRouter —
  подключить `GROQ_API_KEY` (бесплатный тариф) и/или добавить второй OpenRouter
  ключ по ротации в `aiProviders()`. Мониторинг бесплатных лимитов Vercel/провайдеров
  — вручную по консолям (у проекта нет серверной аналитики, что тоже экономит квоты).

## 10. Юридические документы

`privacy.html` и `terms.html` переписаны под все четыре страны (BY/RU/KZ/UZ):
общий текст + блоки по юрисдикциям (правовые основания, права субъектов данных,
официальные ресурсы, применимое право) с переключателем страны на странице.
Страна подхватывается из настроек приложения (`localStorage.nevioCountry`).
В `privacy.html` раскрыта передача IP на ipapi.co (подсказка страны) и
Firebase-синхронизация режима учителя. Язык юридических документов — русский;
перевод на казахский/узбекский — по запросу отдельным этапом (юридический
текст лучше переводить с проверкой).

## 11. Синхронизация прогресса между ботом и сайтом — ПРОПУЩЕНО (решение владельца)

**Статус: пропущено по решению владельца — не реализовывать** (пока явно не будет
запрошено заново). Раздел оставлен как справочный.

**Текущее состояние:** прогресс ученика (и вся история) хранится в `localStorage`.
Telegram Mini App и обычный браузер — это два разных хранилища, даже если открыт
один и тот же URL: прогресс из бота **не виден** на сайте и наоборот. Это два
разных набора данных (плюс третий — другое устройство).

Ниже — ранее предложенный (и отклонённый/отложенный) бесплатный вариант на случай
возврата к вопросу:

1. Использовать ту же опциональную **Firebase Realtime Database (тариф Spark,
   бесплатный)**, что заложена для режима учителя (константа `TEACHER_FIREBASE_DB`).
2. В настройках добавить переключатель **«Синхронизировать прогресс»** (по
   умолчанию выключен; кто не включил — работает как сейчас, локально).
3. Идентификатор: анонимный ID генерируется на устройстве; в Telegram
   дополнительно используется `tg.initDataUnsafe.user.id` для привязки бота
   и сайта одного человека (для сайта — короткий код привязки из бота или
   вход по тому же анонимному ID, введённому вручную).
4. Синхронизируется только прогресс (`nevioProgress_v1` по странам): skills,
   тесты, действия. Стратегия слияния простая: по ключу «предмет|тема» берётся
   сумма попыток и верных ответов (или версия с большей датой при конфликте).
5. Правила Firebase те же, что для учителя (раздел «Режим учителя» выше);
   данные анонимные, объём минимален (десятки КБ на пользователя).

Альтернатива без внешних сервисов: кнопки «Экспорт/Импорт прогресса» (JSON-файл
или строка) — перенос прогресса между устройствами вручную, полностью офлайн.

## 12. Геолокация ipapi.co — поведение при исчерпании лимита

- **Лимиты:** бесплатный тариф ipapi.co — до 1 000 запросов/день и 30 000/мес.
  При превышении сервис возвращает HTTP 429 (не блокирует запросы навсегда).
- **Поведение NEVIO:** геолокация вызывается только до первого выбора страны и
  не чаще одного раза в сутки на устройство (guard `nevioGeoChecked`). При
  429/таймауте/сетевой ошибке ответ считается «нет данных» — пользователь
  просто выбирает страну вручную на экране выбора. **Ошибок и сообщений об
  ошибке пользователь не видит** (тихий fallback).
- **Какие данные уходят:** только IP-адрес устройства (плюс стандартные
  технические заголовки HTTP-запроса). Имя, данные Telegram, история и прочее
  на ipapi.co не передаются; ответ сервиса не сохраняется и не используется
  для трекинга. Это раскрыто в `privacy.html` (раздел 1).

## 13. Локализация интерфейса (kk/uz) — что переведено и что нет

- Весь интерфейсный хром переведён: навигация, меню, настройки, формы,
  тесты (настройка, вопросы, результаты), прогресс, режим учителя, задания
  ученика, плейсхолдеры, подписи ошибок. Названия предметов и режимов
  («Что нужно») в KZ/узб. и UZ/узб. интерфейсах переводятся на лету
  (`subjectName()`, `modeLabel()`), значения остаются русскими ключами —
  внутренняя логика и базы знаний не меняются.
- Проверено автоматически (Chromium): для kk и uz — аудит всех `data-i18n`
  элементов против словарей, аудит заголовков меню, сканирование кириллицы
  на всех ключевых экранах uz-интерфейса.
- Сознательное исключение: **содержимое** статичной справки «Формат и
  критерии» (структура экзамена, критерии, советы) и текст ИИ-ответов — на
  русском. Перевод образовательного контента на kk/uz — отдельный этап
  (требует предметной вычитки), интерфейс от него не зависит.
- Юридические страницы (privacy/terms) — на русском с переключателем
  юрисдикции; перевод на kk/uz — по запросу.

## 15. Устойчивость к исчезновению бесплатных моделей OpenRouter

- В ротации 15 моделей OpenRouter (`:free`) + роутер `openrouter/free` и 3
  модели Groq free tier. Если модель удалена/снята с бесплатного доступа, API
  вернёт 404/429/401 — `callProxy` автоматически переходит к следующей модели
  и следующему провайдеру. Пользователь увидит ошибку только если
  **одновременно** недоступны все модели всех провайдеров.
- Список сверялся с открытыми источниками на июнь–август 2026; его нужно
  обновлять раз в 1–2 месяца по https://openrouter.ai/models?q=%3Afree
  (смотреть модели с суффиксом `:free` и ценой $0). «Мёртвые» записи в списке
