# NEVIO — образовательный ИИ-помощник 🇧🇾

NEVIO — веб-приложение и Telegram Mini App для учеников, учителей и воспитателей Беларуси. Оно помогает готовиться к ЦТ/ЦЭ, разбирать задачи, создавать конспекты, планы уроков и тренировочные тесты.

## Архитектура

```text
Браузер / Telegram Mini App
          │ POST /api/chat (тот же домен)
          ▼
Vercel Function api/chat.js
          │ ключ только в OPENROUTER_API_KEY
          ▼
OpenRouter → openrouter/free
```

Отдельный постоянно работающий сервер не нужен: API запускается как Vercel Function. Ключ OpenRouter не отправляется в браузер и не хранится в `index.html`.

## Обязательная настройка после деплоя

> **Важно:** предыдущий ключ был опубликован в клиентском HTML и остаётся в истории Git. Его необходимо отозвать, даже если он пока работает. Не используйте его повторно и не присылайте новый ключ в чат или коммит.

1. В [OpenRouter Keys](https://openrouter.ai/keys) удалите старый опубликованный ключ и создайте новый.
2. Откройте проект в Vercel: **Settings → Environment Variables**.
3. Добавьте секрет:
   - Name: `OPENROUTER_API_KEY`
   - Value: новый ключ OpenRouter
   - Environments: Production, Preview и Development
4. Выполните **Redeploy** последнего деплоя.
5. Откройте `https://ваш-домен/api/chat`. Исправная конфигурация выглядит так:

```json
{
  "status": "ok",
  "service": "NEVIO AI proxy",
  "configured": true
}
```

Если `configured` равно `false`, переменная не добавлена в окружение этого деплоя или после её добавления не был выполнен Redeploy.

## Локальный запуск

Требуется Node.js 20+ и аккаунт Vercel.

```bash
cp .env.example .env.local
# Впишите новый ключ только в .env.local — этот файл игнорируется Git.
npm run dev
```

Открывайте адрес, который покажет `vercel dev`. Простое открытие `index.html` через `file://` не запускает функцию `/api/chat`.

## Проверки

```bash
npm test
npm run check
```

Тесты проверяют:

- корректную сборку SSE-событий, разрезанных между сетевыми пакетами;
- обработку heartbeat-комментариев OpenRouter;
- понятную ошибку при отсутствующем ключе;
- валидацию входных сообщений;
- передачу потокового ответа через Vercel Function;
- повтор запроса при временной ошибке `429`;
- отсутствие API-ключа в ответах клиенту.

## Почему ответ больше не должен зависать

В клиенте и API предусмотрены:

- таймаут подключения, таймаут бездействия потока и общий лимит ожидания;
- полноценный SSE-парсер с буфером для фрагментированных JSON-событий;
- обработка ошибок, пришедших уже после HTTP `200` внутри потока;
- ограниченные повторные попытки вместо бесконечного индикатора;
- явные сообщения для ошибок конфигурации, лимитов и недоступности моделей;
- сохранение введённого текста, если запрос не удался.

## Основные файлы

- `index.html` — интерфейс и клиентская логика;
- `sse-parser.js` — небольшой SSE-парсер без внешних зависимостей;
- `api/chat.js` — безопасный прокси к OpenRouter для Vercel;
- `.env.example` — пример переменных окружения;
- `test/` — тесты на встроенном `node:test`.
